# PYGEMC Release 0.5.0

This version includes:

- CAD mesh references in geometry parameters, leaving descriptions available for descriptive text.

<br/>

# Release notes

## API

### CAD

- `gemc-sqlite -cad` stores each CAD mesh reference and scale in the geometry `parameters` column.
  The optional `description` field is preserved as descriptive text.

<br/>

## Documentation

- Added a CI workflow guide covering tests, releases, PyPI trusted publishing, the GEMC integration dispatcher,
  required permissions, cross-repository contracts, and safe workflow rollout.

<br/>

## Tests

- Updated the GEMC compatibility-test dispatcher to target its dedicated workflow. Successful trusted
  compatibility runs now rebuild and publish GEMC images, so pygemc-only updates propagate without
  creating skipped GEMC Deploy and Binary Tarballs workflows.

<br/>

## Compatibility notes

- CAD parameters use `<mesh path>, <scale>`. GEMC and PyVista continue to read databases that store
  a numeric scale in `parameters` and the mesh path in `description`.

<br/>

## Detailed list of changes and fixes

- CAD YAML and JSON uploads now write `parameters = "<cad_dir>/<mesh file>, <scale>"`; omitted scales
  default to `1`.
- PyVista resolves relative mesh parameters beside the SQLite database and under its `<system>/`
  subdirectory, supporting generated layouts such as `ltcc/stls`.
