# PYGEMC Release 0.5.0

This version includes:

- CAD mesh references in geometry parameters, leaving descriptions available for descriptive text.
- Canonical serialization of optional geometry metadata as ASCII `NULL` or SQLite `NULL`.

<br/>

# Release notes

## API

### Geometry

- `GVolume` normalizes empty and legacy unset spellings to `None` before publishing. ASCII output uses the
  `NULL` token, while SQLite output stores an actual SQL `NULL`, matching GEMC's typed geometry boundary.
- Added `GVolume.publish_passive()` for geometries that use GEMC2's frame-rotation placement convention.
- `make_tube()` now defaults to a full azimuth, while `make_polycone()` validates its arrays and serializes
  the plane count with the `counts` unit. The box, tube, and polycone builders also support detector-specific
  numeric formatting through the `GVolume` constructor's `value_formatter` option.

### CAD

- `gemc-sqlite -cad` stores each CAD mesh reference and scale in the geometry `parameters` column.
  The optional `description` field is preserved as descriptive text.

### PyVista

- Volumes with `visible = 0` and boolean-construction `Component` volumes no longer create scene actors.
  Invisible mothers still contribute their transforms to visible daughters.
- Failed or incomplete boolean operations are omitted instead of displaying a non-physical construction
  operand as a fallback.
- Elliptical-tube shells cut by full-depth tube sectors are generated directly, preserving LTCC elliptical
  mirrors when generic mesh booleans cannot resolve their thin curved surfaces.

<br/>

## Documentation

- Added a CI workflow guide covering tests, releases, PyPI trusted publishing, the GEMC integration dispatcher,
  required permissions, cross-repository contracts, and safe workflow rollout.

<br/>

## Tests

- Added direct coverage for optional geometry metadata at the ASCII and SQLite serialization boundaries.
- Added geometry API coverage for passive publication, solid-builder defaults, polycone validation, and custom
  numeric formatting.
- Updated the GEMC compatibility-test dispatcher to target its dedicated workflow. Successful trusted
  compatibility runs now rebuild and publish GEMC images, so pygemc-only updates propagate without
  creating skipped GEMC Deploy and Binary Tarballs workflows.

<br/>

## Addressed issues

- No issues assigned to this milestone.

<br/>

## Compatibility notes

- CAD parameters use `<mesh path>, <scale>`. GEMC and PyVista continue to read databases that store
  a numeric scale in `parameters` and the mesh path in `description`.

<br/>

## Detailed list of changes and fixes

- CAD YAML and JSON uploads now write `parameters = "<cad_dir>/<mesh file>, <scale>"`; omitted scales
  default to `1`.
- PyVista resolves relative mesh parameters beside the SQLite database and under its `<system>/`
  subdirectory, supporting generated layouts such as `ltcc/stls`.
- PyVista skips meshing volumes marked invisible and boolean operands that exist only to construct another
  solid.
- PyVista no longer substitutes the first operand when a boolean-result mesh cannot be built.
- PyVista builds elliptical shell sectors analytically without exposing their boolean construction operands.
