# PYGEMC Release 0.4.0

This version includes:

- PyVista variation filtering with `--pyvista-variation`
- Batched PyVista rendering for large geometries with `--pyvista-fast`
- p, theta, and phi residual plots with per-particle CLI filtering
- CAD volume definitions in a single YAML/JSON file, uploaded to SQLite with `gemc-sqlite -cad` <span
  style="color:orange">(upcoming in the next release)</span>
- Optional per-volume `scale` for CAD meshes, plus the `gemc-cure-mesh` utility that simplifies and
  repairs CAD meshes for Geant4 <span style="color:orange">(upcoming in the next release)</span>
- PyVista rendering for SQLite CAD volumes, including STL mesh display with the authored visual
  attributes <span style="color:orange">(upcoming in the next release)</span>

# Release notes

## Analyzer

- GEMC's `save_original_track` option saves the original track ID (`otid`), original particle ID (`opid`),
  and original momentum (`opx`, `opy`, `opz`) in true-information output. This provides the
  original-track reference needed for residual plots.
- The analyzer now derives and plots the p, theta, and phi residuals as `delta_p`, `delta_theta`, and
  wrapped `delta_phi` for hits whose `pid` matches `opid`. The residual is the value at the hit minus the
  original-track value.
- Added per-particle plotting through the Python API `pid` argument and the CLI `--pid <PDG ID>` option,
  for example `gemc-analyzer b2_t0_true_info.csv delta_p --data true_info --pid 2212`. Empty PID
  selections display a concise message and exit normally without a Python traceback.

## API

- `-pv`, `-pvb`, and `-pvvtk` render only the first published variation by default, and
  `--pyvista-variation NAME` selects a specific variation without changing SQLite or ASCII output.
- `GConfiguration.show()` prints a variation/run table instead of a compressed `(Variations, Run)` tuple
  when more than one variation is used.
- The variation/run table now records each variation's run at publish time instead of repeating the final
  run.
- `GConfiguration.show()` now prints the variation selected for PyVista rendering when `-pv`, `-pvb`, or
  `-pvvtk` is used.
- Added `--pyvista-fast`, `--no-pyvista-fast`, and `--pyvista-fast-threshold N`. PyVista now defers actor
  creation until display/export time and automatically batches large scenes above the threshold.
- <span style="color:orange">(upcoming in the next release)</span> `gemc-sqlite -cad <file>` uploads CAD
  volume definitions from a single YAML (or JSON) file into the `geometry` table. Each entry becomes a
  volume with `solid="CAD"` and the mesh path in `description`, so GEMC3's SQLite factory loads it like any
  other volume. Only volumes listed in the file are uploaded, hence loaded; STL files present on disk but
  absent from the file are ignored. `defaults:` apply to every volume and are overridden per volume, and
  the familiar `sensitivity` and `identifiers` keys are accepted as aliases for `digitization` and
  `identifier`. This is the modern replacement for the clas12Tags `cad_<variation>.gxml` mechanism.
- <span style="color:orange">(upcoming in the next release)</span> A CAD volume may carry an optional
  uniform `scale` attribute in the YAML/JSON definition (for example `scale: 10` for a mesh drawn in
  centimetres). The factor is stored in the geometry `parameters` column, which CAD solids do not
  otherwise use, and the GEMC CAD builder applies it on top of the millimetre interpretation, so a mesh
  can be resized without editing its file.
- <span style="color:orange">(upcoming in the next release)</span> PyVista now displays CAD volumes loaded
  from SQLite when `-pv`, `-pvb`, or `-pvvtk` is used. The viewer reads the STL mesh path from the
  volume's `description`, resolves relative paths next to the SQLite database, applies the CAD `scale`,
  position, and rotation, and renders the mesh with the volume's current color, opacity, visibility, and
  style attributes.
- <span style="color:orange">(upcoming in the next release)</span> New `pygemc.utilities` package with
  `cure_mesh()` and the `gemc-cure-mesh` command line, which simplify and repair CAD meshes
  (STL/PLY/OBJ/...) for Geant4's `G4TessellatedSolid`. The pipeline welds coincident vertices, drops
  tiny disconnected components, decimates with quadric edge collapse down to a target facet count,
  repairs non-manifold edges, closes holes, and re-orients facets coherently and outward. This turns
  heavy, non-watertight scans into fast-loading solids and removes the "holes / wrong orientation /
  negative volume" tessellated-solid warnings. Backed by `pymeshlab`.

## Examples

- Added `geometry_source/htcc/cad/cad__default.yaml` as the CAD-definition equivalent of the existing
  `cad_default.gxml`, uploadable with `gemc-sqlite -cad cad__default.yaml`.
- Added the `cad` example (`examples/basic/cad`): the heart, lungs, and liver imported from STL as CAD
  volumes, each a `dosimeter` sensitive detector under a gamma radiation source, with per-organ `scale`,
  `position`, color, and tissue material authored in `stls/cad__default.yaml`. The organ meshes are
  simplified and repaired with `gemc-cure-mesh`.

## Detailed list of changes and fixes

- The `Publish PyPI` workflow can now be triggered by a published GitHub release and uses that release's
  tag to build and publish the package. Stable releases always publish to PyPI, while pre-releases are
  skipped; the existing manual `workflow_dispatch` with the TestPyPI option is unchanged.
- `gemc-sqlite` now binds user-supplied filter values as SQLite parameters and validates `-what` column
  names against the selected table schema before building a query.
- `gcad.py` accepts an optional `scale` key per CAD volume and stores it in the geometry `parameters`
  column; the GEMC CAD builder (`buildSolid.cc`) reads it and applies `SetScale(CLHEP::mm * scale)`.
- `pyvista_api.py` now handles `solid="CAD"` volumes by reading the STL from `description`, resolving
  relative mesh paths against the SQLite database location, applying the CAD scale, and then using the
  existing PyVista render-entry pipeline for placement and display attributes.
- Added the `pygemc.utilities` package with `cure_mesh()`, registered the `gemc-cure-mesh` console-script
  entry point in `pyproject.toml`, and declared `pymeshlab` as a dependency.
